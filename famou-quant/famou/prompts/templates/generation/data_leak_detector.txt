## Common Data Leakage Patterns

### Time Series Leakage
- **Future information**: Using test period data to predict past values
- **Look-ahead bias**: Calculating statistics using future data points
- **Target leakage**: Including future target values as features
- **Example**: Using test.csv's closing price to predict training period's trend

### Train-Test Contamination
- **Preprocessing before split**: Scaling/encoding using combined train+test statistics
- **Imputation before split**: Filling missing values using test data information
- **Feature engineering before split**: Creating features using test set information

### Target Leakage
- **Direct inclusion**: Using target variable or derived values as features
- **Reverse causality**: Features that are consequences of the target
- **Data leakage through IDs**: Row IDs or timestamps that encode target information

### Cross-Validation Leakage
- **Improper grouping**: Group-aware CV not used when data has groups
- **Time-based split**: Random CV instead of time-based CV on time series
- **Data augmentation**: Augmentation done before CV split

### File-Based Leakage
- **Test set files**: Reading test.csv, submission.csv in training code
- **External data**: Using competition's test labels through external sources
- **Sample submission**: Using sample_submission.csv patterns to infer targets

## Key Principles

- **First rule of ML competitions**: Never use test data in training
- **Preprocessing rule**: Fit scalers/imputers on training data only, transform validation/test
- **Time series rule**: Use time-based CV, not random CV
- **Feature engineering rule**: Create features using only historical data available at prediction time
- **File access rule**: Only read training data files during development
