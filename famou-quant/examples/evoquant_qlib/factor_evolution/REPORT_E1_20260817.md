# 实验报告：LLM 驱动的因子公式演化（E1 / 2026-08-17）

**实验 ID** `factor_evolution_20260817_063502_86f5`
**状态** 已完成 30/30 迭代，26.6 分钟
**结论一句话** 链路全程跑通，相对种子有**真实且质变的改进**（RankIC ×2.4，且修复了种子的分段反号问题）；
但**搜索在第 1 步就到顶**，其后 29 轮只产出了同一个因子的近似复制品（两两 Spearman 0.88–0.99），
且**没有任何样本外验证**。因此这是一次成功的**系统验证**，不是一个可信的**因子发现**。

## 2. 结果

### 2.1 种子 vs 最优

| 指标 | 种子（20 日反转） | 最优 `1_0_1` | 变化 |
|---|---|---|---|
| **RankIC** | +0.0184 | **+0.0442** | **×2.4** |
| ICIR | +0.092 | **+0.275** | ×3.0 |
| Sharpe（多空十分位） | **−0.90** | **+1.23** | **符号翻转** |
| 分段 RankIC（4 段） | +0.029 +0.042 +0.049 **−0.047** | +0.031 +0.038 +0.051 **+0.057** | **第 4 段由负转正** |
| 有效天数 | 243 | 243 | — |

**分段那一行是本次最有价值的结果。** 种子在 2014 年第四季度失效（−0.047），
而演化出的因子四段全正且单调上升。这是**质的改变**，不是把一个数字调高——
它意味着新因子不是靠某个区间的运气拿到高分。

### 2.2 运行统计

```
迭代        30/30          程序      32（30 候选 + 2 种子）
Rollout     30             有效      30/30
前视检测    0 次触发        拒绝      0
LLM         63 次调用       tokens   319,523 in / 145,391 out
耗时        1593s（26.6 分钟）
岛屿        island0 best 0.0442 avg 0.0400 | island1 best 0.0404 avg 0.0372
```

漏斗全程无损耗：发起 30 → 生成 30 → 评估 30 → 有效 30。
**LLM 一次都没有写出前视因子**，也没有写出跑不通的代码。

### 2.3 最优因子做了什么

`1_0_1`：五个截面排序信号的线性组合，全部是**短期反转**方向。

| 权重 | 信号 |
|---|---|
| 0.30 | VWAP 乖离反转 `-(close-vwap)/vwap` |
| 0.25 | 成交量放大的 1 日反转 `-ret1 × √(vol/vol_ma5)` |
| 0.20 | K 线实体反转 `-(close-open)/(high-low)` |
| 0.15 | 3 日反转 |
| 0.10 | 5 日 VWAP 反转 |

相对种子（单一 20 日收益反转），它把反转做到了**更短的周期**（1/3/5 日而非 20 日），
并引入了**日内信息**（VWAP 乖离、K 线形态）和**成交量调节**。
所有子信号都做了截面 percentile rank，天然抗极值。

## 3. 三个关键发现

### 3.1 改进是真的，但**全部发生在第 1 步**

最优解是 **iteration 1、generation 1** 的产物。整整 30 轮里只有 **1 次"刷新最优"事件**。

```
种子      0.0184
iter 1    0.0442  ← 最优，此后 29 轮无人超越
iter 2-30 0.0335 ~ 0.0440（全部低于 iter 1）
```

第一次变异就吃掉了全部收益，其后的搜索**没有产生任何价值**。

### 3.2 多样性坍缩：30 个候选是同一个因子

实测 dev 段日均截面 Spearman：

```
              1_0_1   13_0_2   8_1_3   4_1_2   种子
1_0_1         1.000    0.989   0.953   0.884   0.226
13_0_2        0.989    1.000   0.956   0.901   0.220
8_1_3         0.953    0.956   1.000   0.942   0.152
4_1_2         0.884    0.901   0.942   1.000   0.167
种子          0.226    0.220   0.152   0.167   1.000
```

**候选之间 0.88–0.99，与种子只有 0.15–0.23。**
即：LLM 在第一步跳到了一个新区域，然后**原地打转**——
30 份代码的 docstring 结构几乎一致，都是"截面排序的短期反转复合因子"，
分数全部挤在 0.0335–0.0442 这个窄带里。

两个岛屿也没有拉开差异（best 0.0442 vs 0.0404，同属一族）。

### 3.3 RankIC 和 Sharpe 不同步

最高 RankIC 是 `1_0_1`（0.0442，Sharpe +1.23），
但**最高 Sharpe 是 `8_1_3`（+1.77，RankIC 只有 0.0390，排第 21）**。

优化 RankIC 并不等于优化组合收益。当前 `combined_score` 只认 RankIC，
所以搜索压力从未指向 Sharpe——这是设计选择（你选的），但结果值得注意。

## 4. 这次实验**不能**说明什么

按重要性排序：

1. **零样本外验证。** 全部 32 个程序只在 visible_dev（2014）上评过分。
   E1 的 `sealed_promotion`（2015）和 `final_test`（2016）**一个字节都没读**。
   所以 0.0442 是**样本内**数字，不构成任何泛化证据。

2. **选择效应未扣除。** 从 32 个候选里挑最高分，天然带 winner's curse。
   你自己的 `exp1_phenomenon` 在 E1 上测过这个量级：K=50 时约 **0.0037**。
   ⚠️ 那是用 LightGBM 配置池测的，候选类不同，此处只能当**数量级参考**，不能直接相减。
   但方向明确：0.0442 的真实值应低于此。

3. **E1 是 development episode，结果永不进论文主结果**（`splits_v2.yaml:75`）。
   这次是方法调试，不是评估。

4. **单次运行，无重复。** 没有换 seed 重跑，无法区分"方法有效"与"这一次运气好"。

5. **前视检测通过 ≠ 因子一定正确。** 因果性探针只抽查了 6 天。它能拦住系统性前视
   （已实测拦下 4 类，包括直接返回标签），但不是形式化证明。

## 5. 建议的下一步

按性价比排序：

| 优先级 | 动作 | 理由 |
|---|---|---|
| **高** | 用 2–3 个不同 seed 重跑 | 现在无法区分方法有效与单次运气。成本仅 ~27 分钟/次 |
| **高** | 解决多样性坍缩 | 29/30 的算力被浪费在复制品上。可提高 temperature、增加岛屿间差异、或在 prompt 里显式要求与已有候选低相关 |
| **中** | 把 `1_0_1` 送 sealed_promotion（2015）跑一次 | 这是唯一能把"样本内"变成"有证据"的动作。但会花掉 E1 的 sealed 预算 |
| **中** | 考虑把 Sharpe 纳入适应度 | 目前最高 Sharpe 的候选排名第 21，搜索完全没往那个方向使劲 |
| **低** | 把 `adjclose/change/factor` 三列也传给候选 | 信息上冗余（close 已后复权），收益存疑 |

**暂不建议**动 E11：方法明显还没定型（多样性坍缩未解决、未做 seed 重复），
现在用掉唯一的 post-cutoff episode 太早。

## 6. 附带发现（与本次实验独立）

`reliability/baseline_formula.py` 的 formula incumbent 名实不符。
它用 `-1.0 * ROC20` 并在 docstring 里称之为 "20-day reversal"，但 qlib 的 Alpha158 定义是
`ROC%d = Ref($close, d)/$close`，即 **close[t−20]/close[t]**，是收益率的**倒数**，
因此 `-1.0*ROC20` 关于收益率单调递增——**它其实是动量**。

实测坐实：本实验种子 `-(r)` 与 `-1.0*ROC20` 的截面 Spearman = **−1.0000**，
RankIC 恰好相反（+0.0184 / −0.0184）。

影响：那条线的 incumbent 既命名错误，又因 IC 为负而**翻个符号就能赢**，
削弱了"打败 incumbent 说明找到了教科书之外的东西"这一论证。修法：权重改 `+1.0`。
