# Exp 1 — adaptive overfitting 现象曲线（W2 Go/No-Go 门 #2）

**结论：按 §7-W2 字面判据 = NO-GO**（narrow 池 K=100 的选择性乐观 **0.0036**，门槛 0.010）。
但这不是"现象不存在"，而是"**这个候选类的重训噪声太小**"——现象的量级已由本实验定出标度律，
并给出了达标所需的噪声量。详见 §4 的处置建议。

- 运行：`/opt/conda/envs/quant/bin/python run_exp1.py --n-replicate 24 --n-narrow 128 --n-broad 48
  --workers 32 --threads 4`（3092s，2026-08-11），随后 `analyze_scaling.py`
- 产物：`pool_{replicate,narrow,broad}/{candidates,ic_dev,ic_promo}.csv`、`curve.csv`、
  `scaling.csv`、`results.json`
- 协议：冻结 splits v1 的 **E1**（development episode），train 2008-2013 / dev 2014（242 天）/
  promo 2015（228 天），embargo=2 尾修剪，预处理只在 train 段拟合。**final_test(2016) 全程未触碰。**

## 1. 主结果：现象存在、方向正确、但量级只有门槛的 1/3

narrow 池（官方配置邻域扰动，n=128，模拟已收敛的后期演化搜索）：

| K | dev_sel | promo_sel | **selection** | transfer |
|---|---|---|---|---|
| 1 | 0.07084 | 0.07140 | **−0.00010** | +0.00015 |
| 2 | 0.07235 | 0.07246 | 0.00035 | +0.00121 |
| 5 | 0.07370 | 0.07302 | 0.00115 | +0.00176 |
| 10 | 0.07458 | 0.07338 | 0.00167 | +0.00212 |
| 25 | 0.07554 | 0.07294 | 0.00306 | +0.00169 |
| 50 | 0.07612 | 0.07286 | **0.00372** | +0.00160 |
| 100 | 0.07654 | 0.07338 | **0.00362** | +0.00212 |

`selection = (IC_dev(选中) − IC_promo(选中)) − (池均值 dev − 池均值 promo)`，即扣掉与 K 无关的
regime 漂移后的 winner's curse 本身。

- **分解校准正确**：K=1（随机取一个）时 selection = −0.0001 ≈ 0，说明 2014→2015 的水位变化
  已被干净地扣除，测到的确实是选择压力本身。
- **单调上升且远超噪声**：resampling SE ≤ 0.00008，K=50 的 0.0037 是 ~90 个 SE。
- **K=50 即封顶**：K=50→100 不再增长。这是结构性的，不是采样不足——上界随 `E[max_K z] ∝ √(2lnK)`
  增长，K 翻倍只多 7%。**加候选数救不回来。**

## 2. 机制：winner's curse 被重训噪声锁死

`replicate` 池（官方配置**只换 seed**，n=24）直接测出纯重训噪声地板：

| | sd_dev（242 天） | sd_promo（228 天） | spearman(dev,promo) |
|---|---|---|---|
| 噪声地板 | **0.00177** | **0.00325** | 0.168 |

只换 seed 时 dev 与 promo 表现几乎不相关（另一次独立运行测得 −0.115）——正是"纯噪声"应有的样子。

由此得到近似关系（记 sd_dev² = sd_true² + sd_noise²）：

```
selection(K) ≈ E[max_K z] · sd_noise² / sd_dev        上界 = E[max_K z] · sd_noise
```

两池的对照直接验证了它：

| 池 | sd_dev | **噪声占比** | spearman(dev,promo) | selection(K=25) |
|---|---|---|---|---|
| narrow（n=128） | 0.00265 | **0.444** | 0.459 | **0.00306** |
| broad（n=48，9 维全空间随机） | 0.00573 | **0.095** | 0.741 | **0.00089** |

噪声占比差 4.7 倍，selection 差 3.4 倍。**broad 池反而几乎没有 winner's curse**——候选质量差异大时，
dev 排序主要是信号，选择基本选对。现象只在"候选彼此接近"时才严重，这与论文的定位一致
（gate 要解决的正是后期收敛搜索）。

## 3. 标度律：dev 窗长扫描（零额外训练）

逐日 IC 已落盘，改 dev 窗长只需换天数取均值。取 dev 段**末尾** W 天（紧邻 promo）：

narrow 池，K=100：

| W（dev 天数） | sd_noise | 噪声占比 | **selection 实测** | 理论预测 |
|---|---|---|---|---|
| 20 | 0.00769 | 0.951 | **0.01631** | 0.01877 |
| 40 | 0.00463 | 0.722 | **0.01805** | 0.00985 |
| 60 | 0.00342 | 0.591 | 0.00854 | 0.00658 |
| 120 | 0.00275 | 0.607 | 0.01127 | 0.00536 |
| **242（冻结协议）** | 0.00177 | 0.444 | **0.00361** | 0.00295 |

- 标度律成立：`corr(实测, 预测)` = **0.902**(narrow) / **0.943**(broad)，中位比值 1.40 / 2.15
  （简单理论**低估** 1.4–2 倍，形状对、常数偏保守）。
- `sd_noise ∝ 1/√W` 被数据确认：W 从 242 降到 20，sd_noise 从 0.00177 升到 0.00769（比值 4.3，
  √(242/20)=3.5，量级吻合）。
- **W ≤ 40 时 selection 达 0.016–0.018，远超 0.010 门槛。**

### 3.1 一个比 winner's curse 更强的效应（W 短时出现）

W=40 的 selection(K=100)=0.018 **超过了理论上界** 0.0116。上界公式假定 promo 侧不随 K 变化，
但实测 `transfer(K=100) = −0.00448`：短 dev 窗选出的候选在 promo 上比**随机取一个还差**。
这不是单纯的"高估"，是**主动的逆向选择**——候选在 2014 末段特定 regime 上的过拟合，
到 2015 变成负资产。W=120 也出现（transfer −0.00285）。

⚠️ 但 W 扫描的 transfer 值在各 W 之间跳动（+0.0021 / −0.0028 / +0.0013 / −0.0045 / +0.0011），
不构成单调规律。**resampling SE 严重低估了真实不确定性**：所有重采样都来自同一个 128 候选池，
池层面的不确定性未被计入。这条结论要进论文必须先做多池复现。

## 4. 处置建议（不建议按字面判 NO-GO 就转保守版本）

判据 0.010 是 8/03 在**不知道噪声地板**时纸面设的。现在知道了：在 242 天 dev 窗 + GBDT
候选类上，winner's curse 的物理上界就是 `2.51 × 0.00177 ≈ 0.0044`，**0.010 这个门槛本身
在此配置下不可达**。所以要判的不是"现象够不够大"，而是"哪个配置下够大"。

**达标所需噪声量（可直接作为下一步的验收标准）**：按实测比值 1.4 反解，K=100 要拿到
selection ≥ 0.010，需 `sd_noise ≳ 0.003`（当前 GBDT 为 0.00177，差 1.6 倍）。

三条路，按优先级：

1. **换候选类到 NN（首选）。** §6.3 写明主力搜索空间是"LightGBM 变体 + 小型 MLP/GRU/TCN"，
   今天只测了 GBDT——它是**噪声最小**的那一类。NN 的重训噪声通常显著更大，且 W1 已测得
   promo 侧（2015）GBDT 噪声就有 0.003–0.007，说明 0.003 这个目标并不遥远。
   **下一步应做的实验：把 replicate 池换成小型 GRU/TCN，只测 sd_noise 一个数**，
   ~24 次训练即可判定，不需要跑完整曲线。
2. **序贯累积。** Exp 1 测的是单次选择；真实演化跑几百次连续选择，且 dev 被反复复用。
   累积效应未测，是另一个独立的放大来源。
3. **缩短 dev 窗——⚠️ 不能这么做。** `splits.yaml` 明文："dev 取 1 年是设计决定，
   **冻结后不因结果调整**"。看到 W=40 效果好就去改 dev 窗，正是本论文要批判的那种
   adaptive overfitting。若要改，必须作为 protocol v2、给出与结果无关的理由、保留 v1 并披露。
   本文件把 W 扫描记为**分析性外推**，不改协议。

## 5. 工程记录（复现必读）

- **`feature_pre_filter=False` 全池统一关闭**：开启时 lightgbm 按每个候选自己的
  `min_data_in_leaf` 预剔除特征，使分箱与候选绑定、无法跨候选复用已分箱 Dataset。
  实测开/关会改变树结构（同候选 best_iter 22→44），故对**所有候选（含 anchor）一致关闭**，
  池内可比；代价是 anchor 绝对 IC 与 power_study 略有差异。这是有意的协议选择。
- **单候选算力预算 `num_boost_round=300`**（§6.3 "单候选 ≤10–15 分钟"）。不设上限时
  `lr≈0.05 + num_leaves=512` 的候选实测单个 >19 分钟。本次 **hit_cap = 0/128（narrow）、
  0/48（broad）、0/24（replicate）**——无候选触及上限，该约束未污染结果。
- **吞吐**：单候选独占 ~7s，32 并发下 p50=410s（内存带宽受限，`num_threads=20` 比 8 更慢）。
  128+48+24 候选耗时 3092s。
- **可复现性**：`deterministic=True` + 固定 `num_threads`。在 `feature_pre_filter` 改动之前，
  replicate 池两次独立运行给出逐位一致的 sd/range/spearman。
- **数据口径**：特征侧**不做 dropna**（本快照缺 vwap 字段导致 Alpha158 的 `VWAP0` 整列为 NaN，
  按行 dropna 会清空数据集）；lightgbm 原生处理 NaN，只要求标签非 NaN，
  与 `power_study.daily_rankic` 行为一致。

## 6. 诚实边界（写论文时不得省略）

1. **proposer 是无记忆随机的**，候选间不共享反馈。真实 LLM greedy agent 逐轮依赖 dev 反馈提案，
   adaptive overfitting 只会更强 → 本文测得的是**下界**。
2. **单 episode、单市场态**：dev=2014（牛市尾）、promo=2015（股灾）。E2–E5 未触碰。
3. **池层面不确定性未计入**：2000 次重采样全部来自同一候选池，报告的 SE 只反映重采样噪声。
4. **K=100 的重采样从 n=128 中抽取**，子集重叠度高，该点估计无偏但变异性被低估。
