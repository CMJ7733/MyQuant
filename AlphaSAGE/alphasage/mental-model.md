# AlphaSAGE 心智模型

---

## 1. 这是什么类型的问题？

**在组合搜索空间上学一个采样分布**——不是优化问题，是生成建模问题。

这个重新定位是全文的关键。对比一下：

| | 组合优化（RL/GA 的视角） | 分布学习（GFlowNet 的视角） |
|---|---|---|
| 问题 | 在 `X` 里找最好的 `α*` | 学 `P(α) ∝ R(α)` |
| 成功标准 | `R(α*)` 有多高 | 采样出的一批 α 有多好 + 多不同 |
| 失败模式 | 陷入局部最优 | 分布覆盖不全（漏掉某些模式） |
| 输出 | 一个解 | 一个采样器 |

**一个有用的判断法则**：当你的下游要用**一组**解、且这组解的价值取决于它们**彼此不同**时，就该考虑 GFlowNet 而不是 RL。这个模式在分子设计、神经架构搜索、程序合成里都出现过。

## 2. 需要什么前置知识？

### 必须的

- **公式化 alpha 的基本概念**：表达式树、算子（TsStd、Corr、Rank…）、特征（$close、$volume…）、窗口长度。不知道 `Log(TsStd($low, 10d))` 是什么就读不下去。
- **IC / RankIC / ICIR**：全文的奖励和评价都建立在这上面。ICIR = IC 的时序均值 / 标准差。
- **强化学习的基本框架**：状态、动作、策略、奖励、MDP。至少要知道 `max E[R]` 这个目标长什么样。
- **图神经网络的消息传递**：`h_v ← AGG(h_u for u in N(v))`。

### 核心但可以边读边学

- **GFlowNet**。这是全文的引擎，但论文只在 §2.4 用一段话介绍。如果完全没接触过，建议先读一遍 Bengio et al. 2021 的直觉部分。关键理解：
  - 它把生成看成在 DAG 上从空状态走到终止状态；
  - 学前向策略 `P_F` 和后向策略 `P_B`，让"流量"匹配；
  - 结果是 `P(α) ∝ R(α)`——**按奖励比例采样，不是最大化**。
- **RGCN**（关系图卷积）：普通 GCN 对所有边用同一个 `W`；RGCN 对每种关系类型 `r` 学一个 `W_r`。

### 有帮助的

- **AlphaGen（Yu et al. 2023）**：全文最重要的对照组。理解它的"非平稳边际奖励"设计，才能体会 AlphaSAGE 重构问题的意义。
- **AlphaForge（Shi et al. 2025a）**：AlphaSAGE 的组合阶段直接沿用了它。
- **投资组合理论里"分散化"的价值**：为什么一组低相关的因子胜过一个强因子。

### 不需要的

- 不需要深度的 GFlowNet 理论（细致平衡、子轨迹平衡等变体）——论文只用了 Trajectory Balance。
- 不需要 LLM 相关知识。

## 3. 在研究地图里的位置

```
                          自动化 Alpha 挖掘
                                 │
      ┌──────────────┬───────────┼───────────┬──────────────┐
      │              │           │           │              │
   人工假设       遗传算法       强化学习     生成模型        LLM 驱动
   (Alpha101)     (GP/AutoAlpha) (AlphaGen)  (AlphaForge)   (AlphaAgent)
                                 │                            (Alpha-GPT)
                       ┌─────────┴─────────┐
                       │                   │
                   AlphaQCM          ★ AlphaSAGE
                  (分位数RL)      「别最大化，去采样」
                                        │
                                        └── 引擎来自: GFlowNet (Bengio 2021)
                                            原始应用: 分子设计
```

**AlphaSAGE 的坐标**：它不在"改进 RL"这一支上，而是**跳出了 RL**。它借用的是 GFlowNet 这个来自药物发现的工具，因为那个领域面对的是同一个结构性问题——**你要的是一批候选分子，不是一个最优分子**。

**在更大的 ML 图景里**：

```
GFlowNet 的应用谱系
├── 分子/药物设计（原始动机）：要一批多样的候选化合物
├── 生物序列设计：要一批多样的蛋白质
├── 因果结构发现：要一批可能的 DAG
└── ★ AlphaSAGE：要一批低相关的 alpha 因子
```

共同模式：**离散组合空间 + 需要多个多样的高奖励解 + 奖励评估昂贵**。

## 4. 怎么在脑子里归档这篇论文？

**一句话标签**：*「把 argmax 换成 ∝：用 GFlowNet 在 AST 空间里采样多样的 alpha 因子」*

**三个记忆锚点**：

1. **三个诊断，三个药方**：奖励稀疏 → 稠密多面奖励；序列表示不足 → AST + RGCN；模式坍缩 → GFlowNet。**记住诊断比记住药方重要**——诊断可以迁移到别的问题上。

2. **最大的单项提升来自 GNN**（IC 0.046 → 0.070）。虽然论文的叙事重心在 GFlowNet 上，但消融告诉你，如果只能改一件事，改编码器。

3. **一个缺口**：论文的核心主张是"GFlowNet 带来多样性 → 多样性带来更好组合"，但**中间那一环从未被测量**。整篇论文没有一张"因子池内相关系数"的图。

**该在什么场景想起它？**

- 你的搜索算法总是收敛到一批高度相似的解 → 换 GFlowNet；
- 你在编码程序/公式/分子，用的是序列模型 → 试试图编码器；
- 你的奖励只在终局才有 → 想想能不能造一个"表示对齐"式的稠密中间信号（`R_SA` 的思路很通用）；
- 你在做因子挖掘，想快速改进 → 直接抄 `R_NOV = 1 − max|IC(α, α')|`，它不依赖任何其他组件。

## 5. 一个容易混淆的地方：两个层面的"多样性"

论文里有**两个独立的多样性机制**，读的时候容易混：

| 机制 | 层面 | 作用范围 | 数学形式 |
|---|---|---|---|
| **GFlowNet** | 分布层面 | 最终采样出的 alpha 集合 | `P(α) ∝ R(α)` |
| **熵正则 L_ENT** | 动作层面 | 单步的 token 选择 | `−Σ_t H(π_θ(·\|s_t))` |
| **R_NOV** | 奖励层面 | 与已有因子库的差异 | `1 − max\|IC(α, α')\|` |

三者不是重复的：
- GFlowNet 保证**最终分布**不坍缩；
- 熵正则防止**中间某一步**过早确定（这是局部的，防止 `P_F` 在某个状态上变成 one-hot）；
- `R_NOV` 是**显式的**去重压力，针对的是因子库而非采样分布。

有意思的是：**如果 GFlowNet 真的完美工作，理论上不需要 `R_NOV`**——按 `R_IC` 比例采样本身就会给出多样的因子。`R_NOV` 的存在其实暗示了 GFlowNet 在实践中的多样性不够，需要额外的显式压力。论文没有讨论这个张力。

## 6. 与本次一起学习的另外三篇的关系

```
                    「怎么从数据得到预测信号？」
                              │
        ┌─────────────────────┴─────────────────────┐
        │                                           │
  路线 A：端到端黑箱打分                    路线 B：生成可解释的公式因子
        │                                           │
   ┌────┴────┐                              ┌───────┴───────┐
   │         │                              │               │
StockMixer   VTA                      ★ AlphaSAGE      AlphaBench
（纯 MLP）  （LLM推理+                （GFlowNet+RGCN， （LLM 在这条
            时序骨干）                 追求多样性）      路线上行不行？）
```

- **AlphaSAGE ↔ [AlphaBench](../alphabench/)**：这两篇是最该对照读的。AlphaSAGE 用 GFlowNet 做因子搜索，AlphaBench 系统评测**用 LLM** 做同样的事。AlphaBench 的一个关键发现是——**LLM 极不擅长"不做回测就判断因子好坏"（准确率接近随机猜）**。这反过来支持了 AlphaSAGE 的路线：与其让 LLM 凭直觉判断，不如把 IC 直接做成奖励信号，用一个专门的生成模型去学。另一方面，AlphaBench 发现 LLM 在**搜索**任务上表现不错（EA 优于单链搜索），这和 AlphaSAGE"要种群/分布而非单点"的主张是一致的。

- **AlphaSAGE ↔ [StockMixer](../stockmixer/)**：路线 A vs 路线 B 的直接对照。AlphaSAGE 生成的是 `Log(TsStd($low, 10d))` 这样可读、可审计、可上生产的公式；StockMixer 的权重矩阵没人看得懂。代价是 AlphaSAGE 需要额外的组合阶段（沿用 AlphaForge），而 StockMixer 端到端优化。**注意两者的 IC 不可直接比较**——StockMixer 的 IC 0.043 是单模型日频预测，AlphaSAGE 的 IC 0.079 是 50 个因子组合后的 Mega-Alpha，且持有期 20 天。

- **AlphaSAGE ↔ [VTA](../vta-technical-analysis/)**：对"可解释性"的两种定义。AlphaSAGE 的可解释性是**结构性的**（公式本身就是解释）；VTA 的可解释性是**叙事性的**（LLM 生成自然语言推理链）。前者可审计但抽象，后者好读但可能是事后编的故事——VTA 自己的破坏性实验就显示，当推理信号变得不可靠时，模型会转而更依赖时序分支。

**建议阅读顺序**：StockMixer（建立基础）→ **AlphaSAGE**（搜索范式）→ AlphaBench（评测视角）→ VTA（最复杂）。
